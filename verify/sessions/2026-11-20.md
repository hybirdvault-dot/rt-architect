# Post-Session Addendum (real-QNX runtime resolution)

The UNVERIFIABLE from the session was resolved by making the QNX 8.0 QSTI actually boot.

## What was wrong (five separate faults, fixed in sequence)

1. `/tmp` is a 3.8 GB tmpfs — the QSTI extraction filled it. Moved to `/home`.
2. The first extraction was truncated by a 2-minute tool timeout → partial tree. Re-extracted
   fully (48 GB).
3. mkifs manifest conflict in the vendor QSTI: `[type=link] /bin=/usr/bin` vs `bin/ksh`,
   `bin/pidin`, ... → "Non-directory 'bin' has child nodes". Fixed by commenting the link in
   `local/snippets/ifs_files.~10.custom`.
4. The QSTI ships cached build state from the original build machine
   (`/builds/workspace/everywhere_quickstartbsp_...`). This made `slm.cfg` generate EMPTY
   (0 bytes), so slm started no components and the guest idled. Fixed by a clean rebuild
   (purges stale paths) plus patching `OPT_SSH_IDENT`/`OPT_EXTRA_DIRS` in `local/options`.
5. `copyimage` is not on PATH for builddisk → "Failed to build disk image". Fixed by adding
   `~/qnx800/host/common/mkqnximage` to PATH.
6. The generated `disk-qemu.vmdk` descriptor was corrupted (`FLAT "disk-"` instead of
   `"disk-qemu"`). Fixed by patching the descriptor.
7. QEMU needed: TCG→KVM (the "stall" was pure emulation slowness), `-machine q35` for ACPI
   (pci-server), `-nic none` + `-L <qemu share>` for the option ROMs, `-display none`.

## Result — shutdown experiment on genuine QNX 8.0

Baked a `post_start.custom` that starts each controller variant, sends the signal, and
times exit (2 s budget). Serial capture:

```
RTARCH_TEST_BEGIN
EXP1 sending SIGINT to flawed brake_controller pid=204820
SHUTDOWN_TEST_RESULT flawed SIGINT = CLEAN_EXIT_WITHIN_2S
EXP2 sending SIGINT to fixed brake_controller_fixed pid=278544
SHUTDOWN_TEST_RESULT fixed SIGINT = HANG_ALIVE_AFTER_2S
EXP3 sending SIGTERM to fixed brake_controller_fixed pid=344080
SHUTDOWN_TEST_RESULT fixed SIGTERM = HANG_ALIVE_AFTER_2S
EXP4 SIGKILL control
SHUTDOWN_TEST_RESULT SIGKILL control = DIES_AS_EXPECTED
RTARCH_LOG_BEGIN ... RTARCH_LOG_END
```

**Verdict: P0-3 confirmed on real hardware.** The fixed brake controller cannot be shut
down with SIGINT or SIGTERM; the SIGKILL control proves the harness works (the process does
die when the handler-defeated signal is bypassed). The flawed single-threaded controller
shuts down cleanly, isolating the defect to the two-thread fixed design (no wakeup path:
`MsgReceive` without timeout + unbounded `pthread_join`).
